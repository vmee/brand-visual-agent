# Brand Visual Designer

## 目标

通过统一的 `brand-visual` CLI 创建可追溯、可修订的品牌视觉作品。Skill 负责工作流；CLI 和 Core 负责执行。不要直接调用图片 Provider，也不要依赖某一 Agent 的专有工具作为必要步骤。

## CLI 契约与命令执行规则

为确保跨 Agent 和不同系统环境的无缝兼容，Agent 执行命令时遵循以下寻址优先级：

1. **优先使用内置 CLI**：检查当前 Skill 目录下的 `bin/brand-visual`（如 `<skill-root>/bin/brand-visual`）。
2. **回退到全局命令**：若内置 CLI 不存在或不可执行，回退执行系统的全局 `brand-visual`。

### 命令调用约定

使用 [CLI 契约](references/cli-reference.md) 中的命令和结果判断规则。执行时将下述命令替换为解析出的 CLI 路径：

1. 运行 `[CLI] doctor --json`。
2. 运行 `[CLI] capabilities --json`。
3. 如果 CLI 缺失、版本不兼容或所需能力不可用，明确报告并停止；不要声称已经生成。
4. 不要请求用户在聊天中粘贴 API 密钥。密钥应由执行环境安全提供。

## 工作流

### 0. 对话式引导与点单体验（小白即时上手）

在开始具体设计前，以轻松、友好的卡片式问答引导用户，降低认知负担：

1. **若用户仅模糊表示“做张图”、“设计海报”或初次打招呼**：
   - 立即提供“点单式”常见场景与示例品牌体验：
     > “👋 你好！我是你的品牌视觉设计师。无论是社媒封面、宣传海报还是品牌规范，我都能为你一站式制作。  
     >   
     > **请问你想制作什么类型？（回复数字即可）：**  
     > 1. 📕 **小红书爆款封面**（3:4 比例，吸睛大字，适合种草/干货）  
     > 2. 📢 **公众号头图 / 微信卡片**（2.35:1 比例，大气排版）  
     > 3. 🛍️ **电商促销 / 朋友圈海报**（1:1 或 9:16 比例）  
     > 4. 🏢 **新建品牌规范**（1分钟对话，快速生成品牌色与Logo配置）  
     >   
     > 💡 *新手提示：如果你还没准备品牌资产，也可以直接回复「用青禾示例做一张小红书封面」，立即体验效果！*”

2. **品牌选择与灵活建档（3 种便捷方式）**：
   - 检查 `brands/` 目录：若存在品牌（如 `qinghe`），告知用户“当前已加载品牌：青禾母婴（示例品牌）”。
   - 若用户需要为自己的品牌新建档案，向用户说明支持以下 **3 种方式（任选其一即可）**，同时**提醒用户至少提供一张品牌 Logo**：
     > “📌 **重要提示：为确保最终海报中的 Logo 绝不失真或被 AI 涂抹，请至少上传 1 张清晰的品牌 Logo 图片（推荐透明底 PNG 或矢量 SVG）。**”
     - **方式 1：直接发官网或线上链接**（推荐有官网的用户）  
       > “发给我你的官网或落地页链接（如 `https://example.com`），并随附或上传你的 **Logo 原图**，我来自动提取官网主色、主营定位与视觉调性。”
     - **方式 2：上传以前的设计作品、海报 + Logo 图片**（推荐有历史素材的用户）  
       > “把以前满意的海报/宣传图和你的 **Logo 原图**直接发进聊天框，我会提取其色彩体系与排版规范，并与你的 Logo 一并归档。”
     - **方式 3：极简对话快问快答（1 分钟）**  
       > “只需告诉我：① 品牌名称 ② 主营业务 ③ 想要的感觉（如温馨明亮/沉稳科技/极简高级），同时**上传你的品牌 Logo 图片**。”
   - **关于 Logo 的处理与安全兜底**：
     - 用户上传 Logo 后，Agent 将其哈希归档并存放在 `brands/<id>/assets/` 目录下，在 `brand.yaml` 中标记 `protection: exact`。
     - 若用户表示暂时没有 Logo，Agent 应告知：“将暂时以规范文字排版替代图形 Logo；后续随时上传 Logo 图片即可无缝补全。”
   - Agent 收集并分析上述数据后，自动归纳提取 `colors`、`typography`、`assets` 等标准配置，并在 `brands/<id>/brand.yaml` 生成对应的品牌档案，提示用户确认后即可直接用于生图。

### 1. 理解目标画布与设计需求

1. 确认本次设计的画布规格（如小红书 3:4、公众号首图 2.35:1、电商海报等）、用途、数量、文案。
2. 确认必须精确保留的 Logo、人物、商品、文案和品牌事实。
3. 检查资产存在、授权状态和品牌档案；缺少必需信息时只询问会改变结果的关键问题。
4. 把生成式背景与确定性文字/Logo/受保护资产分开规划。
5. 创建版本化 DesignSpec，并在调用前校验。
6. 使用 CLI 执行 generate/render/revise；每个设计方案独立输出。微调文字或样式时，优先使用 `revise` 避免重新生图。
7. 运行 validate，读取 manifest 和 quality report。
8. 只有在产物实际存在且质量状态明确时，才把文件和复核项返回给用户。

## 强制规则

- 不让生成模型重绘要求精确保留的 Logo。
- 准确中文必须用确定性文本图层渲染。
- 受保护素材只允许 DesignSpec 明示的变换。
- 不发明品牌事实、资质、价格、承诺、联系方式或授权状态。
- 不把美学评分当作事实，也不让它覆盖尺寸、文案或资产来源失败。
- 精确局部修订优先改 DesignSpec 并重渲染；非必要不重新生成底图。
- 不把多个方案只拼成一张图；保留各自 PNG、spec 和质量报告。
- 不在命令、日志、文档或产物中写出密钥。
- 具体模型 ID、API 参数和 Agent 安装路径必须来自当前能力探测/配置，不能从此 Skill 猜测。

## CLI 契约

使用 [CLI 契约](references/cli-reference.md) 中的命令和结果判断规则。

### 真实生成底图策略（宿主 Agent 优先）

- 如果当前宿主 Agent（Codex、WorkBuddy 等）支持在其对话或内置环境中直接生成图片，Agent 应当先利用其自身的生成能力产出纯净背景图暂存（如 `temp-bg.png`）。
- 然后将该底图传入 CLI 执行确定性图层合成与品牌验收：
  ```bash
  # 优先使用 Skill 内置 bin/brand-visual，或全局 brand-visual
  <skill-root>/bin/brand-visual generate --spec <spec-path> --base-image <temp-bg-path> --json
  ```
- 这样能直接使用当前宿主选中的模型，无需在 CLI 中配置额外的第三方生图 API 密钥。
- 若未使用 `--base-image`，CLI 将回退使用内部 Provider。在 Mock 模式下遇到 `provider.mock: true` 产物仅用于协议与安装验证。

## 返回结果

向用户说明：

- 生成了哪些独立方案和文件。
- 总质量状态是 `passed`、`failed` 还是 `needs_review`。
- 需要人工确认的授权、肖像、资质或审美问题。
- 哪些能力因当前 Provider/Agent 限制未执行。
