# 验收测试

## 1. 测试原则

- P0：发布阻塞；P1：重要但可带明确限制发布；P2：增强项。
- 自动化测试报告“观察到什么”，不把未执行步骤写成通过。
- 生成式结果不要求像素相同；契约、品牌约束和确定性图层必须稳定。
- 真实 API 测试为 opt-in，需预算、脱敏素材和显式环境开关。

## 2. M1：Skill、CLI 与安装

| ID    | 优先级 | 用例                               | 预期                                     |
| ----- | ------ | ---------------------------------- | ---------------------------------------- |

| M1-04 | P0     | 同一自然语言 fixture 调用 Mock CLI | schema、状态、目录结构一致               |
| M1-05 | P0     | 重复安装                           | 幂等，不产生嵌套目录或重复副本           |
| M1-06 | P0     | 同名用户文件冲突                   | 不覆盖，返回明确冲突                     |

## 5. M4：端到端与质量

标准任务：使用虚构品牌，生成两张风格不同的中文社交媒体封面；原始 Logo 和人物照片保持不变；随后把第二版标题放大 20%，其他元素保持不变。

| ID    | 优先级 | 验收点             | 预期                                                            |
| ----- | ------ | ------------------ | --------------------------------------------------------------- |
| M4-01 | P0     | 五 Agent 端到端    | 所有支持平台完成同一协议；限制透明记录                          |
| M4-02 | P0     | 产物完整性         | PNG、spec、manifest、quality report、summary 全部存在且哈希正确 |
| M4-03 | P0     | 质量聚合           | P0 失败阻止 completed；人工项产生 needs_review                  |
| M4-04 | P0     | 失败原子性         | 失败目录不会伪装为成功任务                                      |
| M4-05 | P0     | 并发同 ID          | 防止互相覆盖，行为明确                                          |
| M4-06 | P0     | 磁盘不足/写入失败  | 失败可诊断，清理临时文件                                        |
| M4-07 | P0     | 断网/服务不可用    | 明确失败，可安全重试，不产生错误成品                            |
| M4-08 | P0     | 密钥和敏感文件扫描 | 发布包零命中                                                    |
| M4-09 | P1     | 性能/成本基准      | 保存测量值，与批准预算比较                                      |
| M4-10 | P0     | 人工品牌审核       | 文案、Logo、色彩、授权、审美问题有签核记录                      |

## 6. 人工审核清单

- 是否使用了最新且正确的 Logo 变体？
- 文案是否逐字正确，是否包含未经验证的数字、资质或承诺？
- 人物、商品、参考图和字体是否有本次用途的授权？
- 主体是否被不当改变、裁切或生成式修饰？
- 品牌色、留白、视觉层级和可读性是否可接受？
- 目标平台的安全区、尺寸和内容政策是否满足？
- 是否存在文化、偏见、隐私或误导性风险？

## 7. 证据目录建议

```text
test-evidence/<release>/
├── compatibility/<agent>/<version>/
├── provider/<capability-snapshot-id>/
├── fixtures/<fixture-id>/
├── reports/
└── approvals/
```

证据中不得放真实 API 密钥、授权不明的客户素材或完整敏感请求。
