# 产品需求文档（PRD）

## 1. 产品愿景

让企业把品牌规则、已授权资产和视觉工作流封装为一套可审计的设计能力，并通过同一个 `brand-visual-designer` Skill 在不同 Agent 中使用，而不为每个平台重写核心设计逻辑。

## 2. V1 用户与核心场景

### 2.1 用户角色

- 品牌/市场运营：批量制作社交媒体封面、海报和营销图。
- 设计人员：用结构化图层快速生成初稿并做精确修订。
- 开发/Agent 工程师：在多个 Agent 中部署、测试和升级同一 Skill。
- 审核人员：查看资产来源、文案、规则命中和人工复核项。

### 2.2 核心场景

1. 文生图：生成无文字或低约束的背景/氛围素材，再程序化排版。
2. 图生图：以参考图生成视觉变体，同时区分可生成区域与受保护资产。
3. 品牌宣传图：读取品牌 YAML、Logo、字体和配色，生成多个独立方案。
4. 精确修订：例如“标题放大 20%，其余不变”，只修改图层数据并重渲染。
5. 质量检查：检查尺寸、文字、Logo 来源、溢出、安全边距、缺失产物和需人工判断的问题。
6. 跨 Agent 执行：同一输入协议和 CLI 在五个目标 Agent 中工作。

## 3. V1 功能需求

### FR-01 Skill 发现与指导

- 仓库只维护一份 `skills/brand-visual-designer/SKILL.md`。
- 安装器把该源部署到每个目标 Agent 当前支持的位置。
- Skill 能让 Agent 执行：环境检查 → 需求澄清 → 生成 DesignSpec → 调用 CLI → 验证产物 → 返回结果。

### FR-02 统一 CLI

计划提供以下命令；命令在实现前仅代表目标契约：

```text
brand-visual doctor
brand-visual capabilities
brand-visual generate --spec <file>
brand-visual render --spec <file>
brand-visual revise --spec <file> --patch <file>
brand-visual validate --task <directory>
brand-visual skill install --agent <id> --scope <project|user>
```

- 支持 JSON 输出模式和稳定错误码。
- CLI 可脱离任一 Agent 单独运行。
- Provider 能用 Mock 替换，以便无费用测试。

### FR-03 品牌配置

- 读取 YAML 品牌配置和本地资产。
- 表达品牌色、字体候选、Logo 变体、最小留白、禁止事项、语气和法律/资质文案约束。
- 资产必须有稳定 ID、相对路径和 SHA-256（实施时生成）。
- 缺少必需资产时失败或标记 `needs_review`，不得伪造。

### FR-04 图片 Provider

- V1 首个真实 Provider：OpenAI Images API。
- 支持能力探测，不能假设所有模型都有相同的生成、编辑、遮罩、透明背景和输入保真能力。
- 具体模型 ID由环境/配置注入并在运行时验证，不写死在 Core 或 Skill。
- 记录请求元数据、耗时、重试、用量（API 返回时）和结果哈希，但不记录密钥。

### FR-05 程序化排版与合成

- Sharp：读取、规范化、裁切、缩放、颜色空间、合成和导出。
- HTML/CSS + Playwright：复杂中文文本、自动换行、字重、字距、行高和布局测量。
- 最终画布尺寸独立于生成模型原生尺寸。
- Logo 与准确文案默认不进入生成提示词作为最终成品；以图层方式叠加。
- 受保护资产只允许 DesignSpec 明示的变换。

### FR-06 结构化设计与可修订性

- 每个方案保存独立 DesignSpec。
- 每个图层有稳定 ID。
- 修订通过受限 patch 修改 DesignSpec；未命中的图层保持不变。
- 如果修订要求必须重新生成底图，系统先说明影响范围。

### FR-07 输出与追溯

每个任务至少输出：

```text
outputs/<task-id>/
├── variants/<variant-id>.png
├── specs/<variant-id>.json
├── manifest.json
├── quality-report.json
└── logs/run-summary.json
```

`manifest.json` 记录工具版本、配置摘要、输入/输出哈希、Provider 能力快照与状态。日志不得包含密钥和不必要的敏感输入。

### FR-08 质量状态

每项检查和任务总状态使用：

- `passed`：机器检查通过。
- `failed`：确定性要求未满足，任务不可交付。
- `needs_review`：需要人工判断或外部授权确认。

### FR-09 跨 Agent 安装

- 支持项目级和用户级目标，默认优先项目级以降低意外影响。
- 安装前探测目标 Agent 版本和当前官方规则。
- 遇到同名文件先比较哈希；覆盖必须得到明确选择。
- 默认复制以保证 Windows/容器兼容；开发模式可选择符号链接，但必须先验证目标 Agent 支持。
- 安装后执行发现测试与 Mock CLI 冒烟测试。

## 4. 非功能需求

- 安全：密钥不落盘于产物；日志脱敏；输入路径防越界；远程 URL 采用允许策略。
- 可移植：核心业务不导入 Agent 专属 SDK。
- 可测试：Provider、文件系统和时钟可替换；离线测试覆盖主要流程。
- 可观察：结构化日志、稳定 task ID、阶段耗时和明确退出码。
- 可重现：同一 DesignSpec 与同一确定性资产应产生相同布局；远程生成内容不要求像素一致。
- 性能：具体预算在 M1 基准测试后确认，不在文档包中臆测。
- 合规：对肖像、商标、资质、促销承诺和素材授权保留人工审核门禁。

## 5. V1 非目标

- 不开发图形化编辑器、素材库 SaaS、多人协作和云端账号系统。
- 不保证不同 Agent 生成完全相同的创意结果。
- 不用 OCR 结果替代确定性文案来源。
- 不自动判定所有版权、肖像权、广告法或行业资质问题。
- 不在 V1 把 MCP/REST 作为必需执行路径。
- 不承诺兼容没有文件读写、命令执行或网络权限的云端 Agent 环境。

## 6. 成功指标与发布门禁

V1 发布至少满足：

- 五个目标 Agent 均有已记录的安装/发现结果；如某平台当前不支持标准 Skill，必须有明确的受限状态与替代接入方案，不能标记为通过。
- 同一 Mock 任务在所有“支持”平台返回相同 schema 版本和产物结构。
- 真实 OpenAI Provider 完成至少一组生成和一组编辑能力测试，且所用模型/参数有核查证据。
- 精确中文、Logo 资产来源、尺寸和边界检查 100% 通过确定性验收用例。
- “标题放大 20%，其他图层不变”的修订用例通过。
- 密钥扫描、失败路径、网络错误、限流和缺失资产测试通过。
- 人工视觉审核清单完成；遗留 `needs_review` 项被显式记录。

## 7. 待产品确认

- 首批支持的画布预设与社交平台。
- 商业授权字体清单与跨操作系统字体策略。
- API 成本上限、单任务超时和重试预算。
- 数据保留与删除周期。
- 是否允许上传含人物或客户信息的素材到远程 Provider。
- V1 的许可证、发布渠道和维护承诺。
